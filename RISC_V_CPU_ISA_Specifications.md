## 2.2 Register File Architecture & Register Usage (`x0`–`x31`)

### Hardware Implementation (`regfile` Subcircuit)

- **32 Architectural Registers (`x0`–`x31`):** The `regfile` subcircuit contains 31 clocked 32-bit registers (`x1` through `x31`) plus `x0`, which is hardwired directly to a 32-bit constant `0x00000000` (`output_0`). Any write attempt to `x0` (`address_rd = 00000`) routes to an unconnected tunnel (`write_enable_0`), guaranteeing `x0` always reads as `0`.

- **Dual Asynchronous Read Ports:** Two 32-to-1 multiplexers (5-bit select lines `address_rs1` and `address_rs2`) allow simultaneous combinational reading of `data_rs1` and `data_rs2` in a single clock cycle.

- **Single Synchronous Write Port:** A 5-to-32 decoder gated by `write_enable` (`enable_rd_write`) activates the write-enable line of the target register `address_rd` (`rd`), latching `input_data` (`rd_write_value`) on the rising edge of `clk`.

## 2.3 Immediate Encoding & Sign-Extension (`get_immediate_value`)

In RISC-V, immediate operands are packed across instruction bits `[31:7]` with the sign bit always placed at `instr[31]`. The `get_immediate_value` subcircuit extracts these fields using Splitters, appends implicit zero bits for shifted formats, sign-extends them to 32 bits using Logisim Bit Extenders, and selects the active format via an 8-to-1 Multiplexer controlled by `imm_type [2:0]`.

| Format | `imm_type` | Instructions | Instruction Bit Mapping → 32-Bit Immediate Output (`immediate[31:0]`) | Sign-Extension & Shift Rule |
| --- | --- | --- | --- | --- |
| **I-Type** | `000` | `ADDI`, `ANDI`, `ORI`, `LW`, `JALR` | `imm[11:0] = instr[31:20]` | The 12-bit slice `instr[31:20]` is sign-extended by replicating `instr[31]` into bits `[31:12]`. |
| **S-Type** | `001` | `SW` | `imm[11:5] = instr[31:25]`, `imm[4:0] = instr[11:7]` | `instr[31:25]` and `instr[11:7]` are combined into a 12-bit value, then sign-extended through bits `[31:12]`. |
| **B-Type** | `010` | `BEQ`, `BNE`, `BLT`, `BGE` | `imm[12] = instr[31]`, `imm[11] = instr[7]`, `imm[10:5] = instr[30:25]`, `imm[4:1] = instr[11:8]`, `imm[0] = 0` | A constant `0` is appended at bit `0` (2-byte alignment) to form a 13-bit signed branch offset, then sign-extended to 32 bits. |
| **U-Type** | `011` | `LUI` | `imm[31:12] = instr[31:12]`, `imm[11:0] = 12'h000` | `instr[31:12]` is placed into the upper 20 bits; the lower 12 bits are padded with `0x000`. |
| **J-Type** | `100` | `JAL` | `imm[20] = instr[31]`, `imm[19:12] = instr[19:12]`, `imm[11] = instr[20]`, `imm[10:1] = instr[30:21]`, `imm[0] = 0` | A constant `0` is appended at bit `0` to form a 21-bit signed jump offset, then sign-extended through bits `[31:21]`. |

## 2.4 Memory Organization (Byte-Addressed, Word-Aligned)

### Harvard Split-Memory Architecture (`IMEM` and `DMEM`)

The CPU uses separate **Instruction Memory (`IMEM`)** and **Data Memory (`DMEM`)** blocks (as permitted by the project specification's unified-or-separate memory rule), preventing structural hazards between instruction fetches and data loads/stores within a single clock cycle:

1. **Instruction Memory (`IMEM`):** Implemented as a `16M × 32` Logisim ROM block. It is indexed by `current_PC` and outputs the 32-bit `instruction` word combinationally.

2. **Data Memory (`DMEM`):** Implemented as a `16M × 32` Logisim RAM block. It is indexed by `alu_output`, accepts `data_rs2` as its 32-bit write data input, reads combinationally onto `dmem_output` (for `LW`), and writes synchronously on the rising clock edge when `dmemory_write_enable = 1` (for `SW`).

### Byte Addressing and 4-Byte Word Alignment

Standard RISC-V uses **byte addressing**, where consecutive 32-bit words reside at byte addresses that are multiples of 4 (`0x000`, `0x004`, `0x008`, `0x00C`, …). Logisim's `16M × 32` ROM and RAM blocks are **word-indexed** (each slot `0, 1, 2, 3…` holds one full 32-bit word).

To bridge RISC-V byte addresses to Logisim word indices while enforcing 4-byte word alignment, both `current_PC` (before IMEM) and `alu_output` (before DMEM) pass through a **32-bit Splitter** that discards bits `[1:0]` (the byte offset within a word) and routes bits **`[25:2]`** (24 bits) to the memory address port `A`.

Extracting bits `[25:2]` is equivalent to integer division by 4:

$$\text{Word Index} = \lfloor \text{Byte Address} / 4 \rfloor$$

| RISC-V Byte Address | Binary `[7:0]` | Dropped Offset `[1:0]` | Logisim Word Address `[25:2]` | Content in `IMEM` / `DMEM` |
| --- | --- | --- | --- | --- |
| `0x00000000` | `0000 0000` | `00` | `0x000000` (Word `0`) | Instruction 0 / DMEM Word 0 |
| `0x00000004` | `0000 0100` | `00` | `0x000001` (Word `1`) | Instruction 1 / DMEM Word 1 |
| `0x00000008` | `0000 1000` | `00` | `0x000002` (Word `2`) | Instruction 2 / DMEM Word 2 |
| `0x0000000C` | `0000 1100` | `00` | `0x000003` (Word `3`) | Instruction 3 / DMEM Word 3 |

### Data Memory Layout for 2×2 Matrix Multiplication (Row-Major Order)

For the 2×2 matrix multiplication program (C = A × B), matrices are stored in DMEM in **row-major order**. The assembly program initialises the base addresses as follows:

- **Matrix A** (`Base = 0x00`, Logisim RAM words `0x00`–`0x03`):
  `0x00` = A[0][0], `0x04` = A[0][1], `0x08` = A[1][0], `0x0C` = A[1][1]
- **Matrix B** (`Base = 0x10`, Logisim RAM words `0x04`–`0x07`):
  `0x10` = B[0][0], `0x14` = B[0][1], `0x18` = B[1][0], `0x1C` = B[1][1]
- **Matrix C** (`Base = 0x20`, Logisim RAM words `0x08`–`0x0B`):
  `0x20` = C[0][0], `0x24` = C[0][1], `0x28` = C[1][0], `0x2C` = C[1][1]

The element address formula for an N×N matrix starting at byte address `Base` is:

$$\text{Byte Address}[i][j] = \text{Base} + (i \times N + j) \times 4$$

For the 3×3 variant, Matrix A starts at byte `0x00` (words `0x00`–`0x08`), Matrix B at byte `0x24` (words `0x09`–`0x11`), and Matrix C at byte `0x48` (words `0x12`–`0x1A`), with a row stride of 12 bytes.
